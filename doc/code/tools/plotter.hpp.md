# tools/plotter.hpp

**概要**：调试数据「绘图器」发送端的类声明——把 `nlohmann::json` 对象序列化为紧凑 JSON 文本，经 UDP 单播发往本机配套上位机绘图程序，用于实时观测算法内部量（观测器状态、残差、卡方检验、云台响应等）的曲线变化。

> 来源：sp_vision_25 `tools/plotter.hpp`（逐文件迁移，接口与 socket 协议保持一致）。
> 依赖：POSIX socket（`<netinet/in.h>` 提供 `sockaddr_in`；实现文件另用 `<sys/socket.h>`、`<arpa/inet.h>`、`<unistd.h>`）、nlohmann/json 3.11.3、`<mutex>`、`<string>`。
> 注意事项：
> - **端口占用**：本类只做 UDP 发送，不 `bind`、不 `listen`，因此不会占用本地端口，也不存在“端口被占用”导致构造失败的情况。
> - **连接失败**：UDP 无连接，接收端不在线时 `sendto` 不报错、数据包静默丢弃；构造时 `socket()` 失败或 `host` 非法同样不抛异常。
> - **线程安全**：`plot()` 内部用 `mutex_` 串行化，同一实例可被多线程安全调用；不同实例之间不共享锁。
> - **失败时的行为**：发送失败不抛异常、不终止程序、不阻塞调用方，只丢失这一帧调试数据（调试通道不得影响主流程）。
> - **协议固定**：默认目标端口 9870，报文为 `json.dump()` 产生的紧凑 JSON（UTF-8、无换行），一次 `plot()` 对应一个 UDP 数据报；迁移时不得改动，否则上位机不认。

## 类

### `tools::Plotter`

- **职责**：调试数据绘图器的 UDP 发送端。构造时创建 socket 并填写目标地址；每次 `plot()` 把 JSON 序列化为紧凑文本按单播发出；析构时关闭 socket。接收方为配套上位机绘图程序，按键名解析并绘制曲线。
- **生命周期**：一个实例持有一个 socket 描述符；实例**不可拷贝**（拷贝会导致两个对象持有同一描述符并在析构时二次 `close`，属源工程遗留缺陷，迁移时按“行为不变”原则未改动接口，详见报告）。
- **成员变量**：
  - `int socket_`：UDP socket 文件描述符，构造时由 `::socket(AF_INET, SOCK_DGRAM, 0)` 创建，析构时 `::close`；创建失败为 -1。
  - `sockaddr_in destination_`：目标地址结构（IPv4 地址族 + 端口 + 地址），构造时填写后不再变化。
  - `std::mutex mutex_`：串行化 `plot()` 的发送，保证多线程下同一实例调用安全。

## 函数

### `Plotter(std::string host = "127.0.0.1", uint16_t port = 9870)`

- **作用**：构造绘图器，创建 UDP socket 并填写目标地址。
- **参数**：
  - `host`：目标主机地址（点分十进制 IPv4 字符串），默认 `"127.0.0.1"`（本机）。
  - `port`：目标端口，主机字节序 `uint16_t`，默认 9870；内部用 `htons` 转网络序。
- **返回**：无。
- **备注**：`host` 非法时 `inet_addr` 返回 `INADDR_NONE`（255.255.255.255），报文会发往广播地址；`socket()` 失败时 `socket_ = -1`，后续发送静默失败。两种情况都不抛异常。

### `~Plotter()`

- **作用**：析构，关闭构造时创建的 UDP socket（不发送任何结束标记）。
- **参数**：无。
- **返回**：无。
- **备注**：`socket_` 为 -1 时 `close(-1)` 仅失败返回，无副作用。

### `void plot(const nlohmann::json & json)`

- **作用**：把 JSON 对象序列化后作为单个 UDP 数据报发送。
- **参数**：`json` 待发送数据，必须能被 `nlohmann::json::dump()` 序列化。
- **返回**：无（`sendto` 返回值被忽略，发送失败不报错）。
- **备注**：内部加 `mutex_`，多线程可安全调用；报文不加换行符，无应答确认；容器内含 NaN/Inf 等非有限浮点数时 `dump()` 会抛异常并向上传播（本类不捕获）；`sendto` 通常微秒级返回，不阻塞主流程。
